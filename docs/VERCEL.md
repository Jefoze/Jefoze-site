# Jefoze — Vercel + Neon

Портфолио с общей базой PostgreSQL, серверной админкой и загрузкой изображений. Фронтенд собирается Vite; API работает в Vercel Functions. Постоянный процесс и диск на Vercel не нужны.

## Публикация jefoze.vercel.app

1. Откройте проект **Jefoze** в Vercel, подключённый к репозиторию `Jefoze/Jefoze-site` и ветке `main`.
2. В разделе **Storage / Marketplace** подключите **Neon (Postgres)**. Проверьте, что подключение добавило переменную **`DATABASE_URL`** для **Production**. Сервер также понимает `POSTGRES_URL`. Если интеграция создала переменную с другим префиксом, добавьте `DATABASE_URL` со строкой подключения из панели Neon.
3. В **Settings → Environment Variables** добавьте **`ADMIN_PASSWORD`**, минимум 12 символов, для **Production**. Можно использовать пароль из локального `.env`. Не добавляйте префикс `VITE_`: этот пароль должен быть доступен только серверу.
4. В настройках сборки: Framework **Vite**, Build Command **`npm run build`**, Output Directory **`dist`**, Node.js **24.x**. Эти параметры также заданы в проекте.
5. После добавления переменных выполните **Deployments → Redeploy** последнего коммита. Само изменение переменных не обновляет уже опубликованную версию.
6. Откройте `https://jefoze.vercel.app/api/content`: должен вернуться JSON с `data` и `revisions`. Затем откройте **`https://jefoze.vercel.app/#admin`** и войдите с заданным паролем.

Таблицы и начальные данные создаются при первом запросе. SQL вручную запускать не нужно. Пароль из переменных окружения применяется **только к новой базе**. После первого входа менять пароль нужно в разделе безопасности админки; новое значение сохраняется в базе как scrypt-хеш.

Для Preview-развёртываний используйте отдельную Neon-базу/ветку и отдельные переменные окружения. Preview с той же `DATABASE_URL` будет изменять Production-данные.

## Что хранится на сервере

Работы, контакты, статистика, изображения, хеш пароля, сессии и ограничение попыток входа хранятся в Neon. Они общие для всех экземпляров функций и не исчезают после redeploy. Изображения загружаются отдельными запросами и раздаются через `/api/images/...`; в контенте сохраняются только их адреса. Админка уменьшает изображения до 1400 пикселей. Лимит одного JSON-запроса — 2 МиБ, ниже лимита Vercel Functions.

Открытые страницы проверяют изменения каждые 10 секунд, а также при возвращении на вкладку. Скрытые вкладки не опрашивают сервер. При одновременном редактировании устаревшее сохранение отклоняется, чтобы не затереть чужую работу.

Контент не записывается в localStorage/sessionStorage. Язык и тема действуют до перезагрузки. Для входа используется HttpOnly cookie со сроком 12 часов; на Vercel включён Secure. Изменение пароля завершает остальные сессии.

Резервные копии и восстановление настраиваются в Neon. Не удаляйте базу при обновлении сайта. Неиспользуемые загруженные изображения остаются в базе, чтобы сохранённые ссылки и открытые формы не ломались; при необходимости их можно очистить отдельно после резервной копии.

## Локальная разработка

Нужен Node.js 24.

```text
npm ci
```

Скопируйте `.env.example` в `.env`, задайте `ADMIN_PASSWORD`. Если добавить `DATABASE_URL`, локальный сервер использует указанную PostgreSQL-базу. **Не подключайте Production-базу для экспериментов.** Без этой переменной локально используется SQLite в `data/jefoze.sqlite`; на Vercel такой запасной режим отключён.

Запустите `npm run dev:server` и `npm run dev` в двух терминалах. Для проверки собранного сайта выполните `npm run build`, затем `npm start` и откройте `http://localhost:3001`.

Существующая локальная SQLite-база не переносится в Neon автоматически. Локальный пароль и контент остаются на диске; новая облачная база получает исходные работы и контакты из `server/seed.js`.

## Проверки

```text
npm test
npm run build
```

Тесты проверяют API через HTTP с SQLite, сохранность после перезапуска, загрузку изображений, а также PostgreSQL-запросы с PGlite: независимые обработчики функций, общие сессии, ограничения входа и конфликты сохранения. Подключение к реальной Neon и публикация проверяются отдельно после настройки Vercel.

## Если вход не работает

- **404 на `/api/session`**: проверьте, что Vercel развернул актуальный коммит с каталогом `api` и `vercel.json`, а Root Directory указывает на корень репозитория.
- **503 с упоминанием `DATABASE_URL` или `ADMIN_PASSWORD`**: добавьте нужную переменную для Production и выполните Redeploy.
- **500**: проверьте Function Logs и доступность Neon. Не публикуйте строку подключения и пароль в GitHub или переписке.
- **Wrong password** после смены переменной: в существующей базе действует ранее установленный пароль, переменная не сбрасывает его.
- **429**: подождите 15 минут после серии неправильных попыток входа.

`.env`, `.vercel`, локальная база и результаты сборки исключены из Git.
